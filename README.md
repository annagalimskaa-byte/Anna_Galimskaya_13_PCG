# Anna_Galimskaya_13_PCG

ЛАБОРАТОРНАЯ РАБОТА № 1
Цветовые модели
Цель работы
Изучить основные цветовые модели RGB, CMYK и HLS, а также дополнительно XYZ и CIELAB (Lab),
принципы перехода между цветовыми пространствами, понятие цветового охвата (gamut) и проблему
отображения цветов, выходящих за пределы диапазона sRGB. Реализовать desktop-приложение на
Python, позволяющее задавать цвет тремя способами и одновременно отображать его в моделях RGB,
CMYK и HLS (вариант 6).
Задачи работы
В ходе выполнения лабораторной работы были поставлены следующие задачи:
• изучить назначение и область применения цветовых моделей RGB, CMYK, HLS, XYZ и Lab;
• рассмотреть формулы перехода между цветовыми пространствами, включая методы
формирования чёрного канала GCR и UCR;
• изучить понятие цветового охвата и проблему выхода цвета за пределы отображаемого
диапазона;
• реализовать desktop-приложение на Python с одновременным отображением RGB, CMYK и HLS,
тремя способами ввода цвета (числовые поля, слайдеры, палитра) и автоматическим пересчётом
моделей;
• реализовать предупреждение при ограничении цвета до допустимого диапазона;
• дополнительно реализовать поддержку XYZ и Lab с выбором источника света (illuminant);
• покрыть математические функции автоматическими тестами;
• собрать исполняемый .exe файл и разместить исходный код на GitHub.
Использованные средства разработки
• Python 3 — реализация всей логики приложения и математики цветовых моделей.
• Tkinter — встроенная в Python библиотека для графического интерфейса; сторонние библиотеки не
устанавливались.
• unittest — встроенный модуль Python для автоматического тестирования.
• PyInstaller — сборка проекта в единый исполняемый файл (.exe) для Windows.
• Git и GitHub — контроль версий и размещение исходного кода.
Ход выполнения работы
1. Разработка архитектуры приложения
Проект разделён на три слоя: model — математика цвета без единой строчки интерфейса, viewmodel
— единственный слой, который хранит текущий цвет и вызывает функции из model, view — окно на
Tkinter, которое ничего не знает о формулах и только показывает числа, полученные от viewmodel.
Такое разделение позволяет менять интерфейс, не трогая математику, и наоборот.
2. Разработка интерфейса
Созданы три одинаковых по структуре блока — для RGB, CMYK и HLS. Каждый блок содержит слайдер
и числовое поле для каждого параметра, поэтому значение можно задать как перетаскиванием, так и
прямым вводом числа. Чтобы не писать три похожих блока кода, реализован один класс ModelSection,
который просто по-разному настраивается для каждой из трёх моделей.
3. Визуальный выбор цвета
Добавлена палитра из 16 готовых цветов в виде кнопок-образцов. При нажатии на кнопку выбранный
цвет применяется сразу ко всем трём моделям.
4. Реализация функций преобразования
Написаны функции rgb_to_cmyk/cmyk_to_rgb и rgb_to_hls/hls_to_rgb. Для CMYK реализованы два
способа формирования чёрного канала: GCR (чёрный убирается полностью при любой яркости) и UCR
(чёрный подмешивается только в тёмных цветах, начиная с определённого порога). Формулы для
CMYK взяты из методических материалов и проверены на граничных значениях (чистый красный,
чёрный, белый).
5. Автоматический пересчёт моделей
Приложение всегда хранит только один «настоящий» цвет — в формате RGB. При изменении CMYK
или HLS введённые значения сразу переводятся в RGB и сохраняются как основной цвет, а при
следующей перерисовке окна CMYK и HLS вычисляются из этого RGB заново. За счёт этого изменение
одной модели автоматически обновляет две другие.
6. Проверка диапазонов и округление
Реализована функция constrain(), которая приводит значения к допустимому диапазону двумя
способами: clip — обрезка до границы, и scale — пропорциональное уменьшение всех компонентов
сразу. Если после проверки значение изменилось, в интерфейсе появляется предупреждение.
7. Дополнительная часть: XYZ и Lab
Реализован перевод в XYZ и Lab с выбором источника света (D65, D50 или E). Матрица перехода RGB →
XYZ не хранится как готовая константа, а строится заново под выбранный источник света на основе
координат первичных цветов sRGB — то есть при смене источника света результат меняется
автоматически, без правки кода. Для Lab → RGB реализован тот же механизм ограничения диапазона
(clip/scale), что и для CMYK и HLS, так как перевод из Lab действительно может дать значения вне 0–
255.
8. Тестирование
Написаны 17 автоматических тестов (unittest), которые проверяют: совпадение прямого и обратного
перехода RGB↔CMYK и RGB↔HLS, разницу между GCR и UCR на тёмных и светлых цветах, работу
функции constrain() в обоих режимах, а также правильность перевода в Lab по эталонному примеру
(чистый красный → L≈53.24, a≈80.09, b≈67.20).
9. Сборка исполняемого файла
Проект собран в единый .exe файл командой pyinstaller --onefile --windowed --name
ColorLab main.py. Готовый файл не требует установки Python на компьютере, на котором
запускается.
Проблемы, возникшие в работе, и способы решения
1. Неправильный результат при вычислении обратной матрицы для перехода RGB → XYZ.
Причина: при написании функции вычисления обратной матрицы 3×3 индексы миноров были
расставлены неверно.
Решение: результат был проверен умножением обратной матрицы на исходную — должна получиться
единичная матрица. Проверка показала ошибку, после чего формула была переписана и повторно
протестирована.
2. Явно неверные значения XYZ и Lab (например, для чистого красного получались отрицательные и
очень большие числа).
Причина: координаты источника света уже были заданы в шкале 0–100, но код дополнительно
умножал результат на 100, из-за чего числа выходили в два раза больше нужного.
Решение: лишнее умножение было убрано, а результат проверен по эталонным значениям Lab для
чистого красного цвета.
3. Ошибка _tkinter.TclError: bad screen distance "0 8" при запуске окна.
Причина: в конструктор Frame был передан отступ в виде пары чисел (pady=(0, 8)), хотя такая запись
допустима только при вызове .pack()/.grid(), а не при создании самого виджета.
Решение: отступ заменён на одно число (pady=4).
4. На Windows команда python в терминале не находилась.
Причина: в системе была включена заглушка Microsoft Store, которая перехватывает команду python,
если сам Python установлен не через Store.
Решение: использована команда py вместо python, либо выполнено отключение заглушки в Settings →
Apps → Advanced app settings → App execution aliases.
Результаты работы
В результате выполнения лабораторной работы создано приложение Color Lab, которое:
• одновременно отображает выбранный цвет в RGB, CMYK и HLS;
• позволяет задавать значения вводом числа, перетаскиванием слайдера или выбором из палитры;
• автоматически пересчитывает остальные модели при изменении любого параметра;
• дополнительно реализует перевод в XYZ и Lab с выбором источника света;
• показывает предупреждение при выходе значения за допустимый диапазон и позволяет выбрать
способ ограничения — clip или scale;
• покрыто 17 автоматическими тестами;
• собрано в исполняемый .exe файл для Windows;
• содержит исходный код на GitHub.
Вывод
В результате выполнения лабораторной работы разработал desktop-приложение на Python для
работы с цветовыми моделями RGB, CMYK и HLS. Основная сложность возникла при реализации
дополнительной части с XYZ и Lab: матрица перехода зависит от источника света, поэтому её нельзя
один раз посчитать и зафиксировать — пришлось пересобирать её под каждый выбранный illuminant.
Также оказалось, что перевод из Lab обратно в RGB не всегда попадает в диапазон 0–255, поэтому
пришлось реализовать два варианта ограничения значений. Использование встроенной библиотеки
Tkinter позволило обойтись без установки сторонних зависимостей. Сроки выполнения не были
нарушены.
